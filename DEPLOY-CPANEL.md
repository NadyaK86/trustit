# Деплой trustit.by на hoster.by через cPanel (без SSH, через «Setup Node.js App»)

Этот способ подходит, если у вас тариф с cPanel и в нём есть раздел **«Setup Node.js App»** (иногда называется «Node.js Selector»). Он позволяет запускать Node-приложение прямо из панели управления, без командной строки — cPanel сам поднимает процесс через Phusion Passenger и держит его живым (аналог PM2, но встроенный).

Архитектура та же, что в VPS-варианте:
- `trust-site` — статический Astro-сайт, собирается в `dist/`, эта папка становится **корнем сайта** (Document Root домена).
- `admin` — Node-приложение, запускается через «Setup Node.js App», доступно по адресу `trustit.by/admin`.

> В коде уже заложена совместимость с этим способом: добавлен middleware, который сам разбирается с префиксом `/admin`, даже если платформа (в отличие от nginx на VPS) не обрезает его перед передачей в приложение. Ничего вручную для этого настраивать не нужно — просто убедитесь, что используете актуальную версию `admin/server.js` из репозитория.

---

## 1. Загрузка кода на хостинг

Вариант А (проще всего) — через **Git Version Control** в cPanel, если такой пункт есть в панели:
1. cPanel → **Git Version Control** → **Create**.
2. Clone URL: `https://github.com/NadyaK86/trustit.git`
3. Repository Path: например `/home/ваш_логин/trustit`
4. Branch: `main`
5. Жмёте **Create** — cPanel сам склонирует репозиторий.

Вариант Б — через **File Manager**: скачайте архив репозитория (`Code → Download ZIP` на GitHub), загрузите ZIP через File Manager в `/home/ваш_логин/trustit`, распакуйте (правой кнопкой → Extract).

## 2. Собираем статический сайт (`trust-site`)

Соберите `dist/` **локально у себя на Mac** и загрузите готовую папку на хостинг — это надёжнее и быстрее, чем гонять сборку Astro на слабом shared-хостинге:

```bash
# на вашем Mac, в папке trust-site
npm install
```
Создайте `.env` (если ещё нет) на основе `.env.example`:
```ini
PUBLIC_SITE_URL=https://trustit.by
PUBLIC_LEAD_ENDPOINT=/api/lead
```
Соберите:
```bash
npm run build
```

Теперь загрузите содержимое папки `trust-site/dist` (именно **содержимое**, а не саму папку) в `public_html` вашего домена `trustit.by` через File Manager (можно зазипить `dist` в архив, загрузить и распаковать прямо в `public_html`, это быстрее, чем по одному файлу).

> Каждый раз, когда меняете контент через админку, там же появится актуальный `dist/` уже на сервере — эту папку из `public_html` трогать вручную больше не придётся, только при самой первой заливке.

## 3. Настройка Node.js-приложения для админки

cPanel → **Setup Node.js App** → **Create Application**:

| Поле | Значение |
|---|---|
| Node.js version | самая новая доступная (нужна ≥ 20, лучше ≥ 22) |
| Application mode | `Production` |
| Application root | `trustit/admin` (путь относительно домашней папки, где лежит склонированный репозиторий) |
| Application URL | выбираете домен `trustit.by`, в поле подпапки указываете `admin` — итоговый адрес получится `trustit.by/admin` |
| Application startup file | `server.js` |

Жмёте **Create**.

## 4. Переменные окружения

На той же странице приложения (после создания) будет раздел **Environment variables** — добавьте:

| Имя | Значение |
|---|---|
| `ADMIN_PASSWORD` | ваш надёжный пароль (минимум 8 символов) |
| `ADMIN_JWT_SECRET` | случайная строка ≥ 24 символов (сгенерируйте, см. ниже) |
| `SITE_PATH` | `../trust-site` (путь от `admin/` до папки сайта — поправьте, если структура папок на сервере другая) |
| `NODE_ENV` | `production` |
| `SITE_ORIGIN` | `https://trustit.by` |
| `SITE_PREVIEW_URL` | `https://trustit.by` |
| `TELEGRAM_BOT_TOKEN` | токен вашего бота (если уже создали) |
| `TELEGRAM_CHAT_ID` | id чата/канала |

`ADMIN_PORT` и `PORT` задавать не нужно — cPanel назначает порт сам, сервер это уже учитывает.

Сгенерировать `ADMIN_JWT_SECRET` можно на своём Mac:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## 5. Установка зависимостей

На странице приложения в cPanel есть кнопка **Run NPM Install** — нажмите её, cPanel установит зависимости из `admin/package.json` во внутреннее виртуальное окружение.

## 6. Запуск

Кнопка **Restart** (или **Start**, если ещё не запущено) на странице приложения. Статус должен стать зелёным / "Running".

## 7. Проверка

Откройте `https://trustit.by/admin` — должна загрузиться страница входа в админку. Залогиньтесь тем паролем, что указали в `ADMIN_PASSWORD`.

Если видите 404 или 500 — смотрите лог: на странице приложения в cPanel обычно есть ссылка на лог-файл (`stderr.log` в папке приложения), либо через File Manager откройте `trustit/admin/logs`.

## 8. Форма заявок на сайте (`/api/lead`)

Здесь важный нюанс: раздел «Setup Node.js App» умеет проксировать в приложение только тот путь, который вы указали как Application URL (`trustit.by/admin`). Путь `/api/lead`, который использует форма на **главном сайте** (не в админке), находится **вне** этого префикса — значит, по умолчанию он "провалится" в статику `public_html` и даст 404.

Варианты решения:

**Вариант А (проще всего, ничего не трогая):** пусть форма отправляет заявку сразу под префиксом `/admin`, обновите `.env` сайта перед сборкой:
```ini
PUBLIC_LEAD_ENDPOINT=/admin/api/lead
```
и пересоберите/перезалейте `dist/`. `/admin/api/lead` попадёт в то же Node-приложение — сработает сразу, без правки Apache.

**Вариант Б (чуть аккуратнее по адресам, но требует правки Apache):** добавить правило редиректа в `.htaccess` в корне `public_html`, чтобы `/api/lead` тоже проксировался в приложение:
```apache
RewriteEngine On
RewriteCond %{REQUEST_URI} ^/api/lead$
RewriteRule ^ /admin%{REQUEST_URI} [PT,L]
```
Это может не сработать на 100% на всех конфигурациях cPanel (зависит от того, как именно там настроен Passenger), поэтому **Вариант А надёжнее** — рекомендую его.

## 9. Как публиковать изменения контента дальше

Как и в VPS-варианте — заходите в `https://trustit.by/admin`, редактируете контент, жмёте «Собрать сайт». Единственное отличие: убедитесь, что у пользователя, от имени которого работает Node-приложение, есть права на запись в папку `trust-site/dist` внутри `public_html` (обычно так и есть, раз это один и тот же аккаунт хостинга) — тогда пересборка сразу обновит то, что видят посетители сайта.

## Что выбрать: VPS+SSH+PM2 (`DEPLOY.md`) или cPanel (этот файл)?

- **VPS-вариант** — больше контроля, привычная связка nginx+PM2, чуть более гибкая настройка (например, легче добавить редиректы, кэширование, HTTP/2). Требует SSH-доступа и минимальных навыков администрирования Linux.
- **cPanel-вариант** — быстрее стартовать, не нужен SSH и работа с терминалом на сервере, всё через привычный веб-интерфейс. Чуть менее гибкий (например, момент с `/api/lead`, описанный выше).

Раз у вас уже есть SSH-доступ к VPS и оба варианта в целом рабочие — можно ориентироваться на `DEPLOY.md` как на основной путь, а этот файл держать про запас, если вдруг тариф сменится на чисто cPanel-хостинг без root-доступа.
