# Деплой trustit.by на hoster.by через cPanel (без SSH, через «Setup Node.js App»)

Этот способ подходит, если у вас тариф с cPanel и в нём есть раздел **«Setup Node.js App»** (иногда называется «Node.js Selector»). Он позволяет запускать Node-приложение прямо из панели управления, без командной строки — cPanel сам поднимает процесс через Phusion Passenger и держит его живым (аналог PM2, но встроенный).

## Схема размещения (когда на хостинге несколько сайтов, и под trustit.by уже есть отдельная папка)

Раз `trustit.by` — это уже готовый корень домена (сейчас там лежит содержимое `dist`), а `admin` должна физически жить внутри неё (`trustit.by/admin`), раскладка такая:

```
/home/ваш_логин/
├── trustit.by/              ← корень домена, сюда Astro пишет собранный сайт
│   ├── index.html
│   ├── _astro/
│   ├── ...остальные страницы...
│   └── admin/                ← Node-приложение (сюда копируете папку admin/ из репозитория)
│       ├── server.js
│       ├── package.json
│       └── public/
│
└── trust-site-src/           ← НОВАЯ приватная папка — НЕ должна быть доступна из веба.
    ├── src/                   ← сюда копируете папку trust-site/ из репозитория
    ├── astro.config.mjs
    ├── package.json
    └── public/
```

**Важно, почему так:** исходники Astro-проекта (`src/`, `package.json`, `node_modules` и т.д.) не должны лежать в публичной папке домена — это и небезопасно (кто угодно потенциально может попытаться скачать `package.json` по прямой ссылке), и не нужно посетителям сайта. Поэтому держим исходники отдельно, а собранный результат (`dist`) Astro будет писать прямо в `trustit.by` через переменную `ASTRO_OUT_DIR` (уже настроено в коде — см. ниже).

> **Про безопасность папки `admin`:** так как `admin/` лежит физически внутри той же папки, куда Astro пишет собранный сайт, при пересборке есть риск, что Astro случайно удалит её вместе со старыми файлами. Чтобы этого не произошло, в `astro.config.mjs` уже отключена автоматическая очистка выходной папки (`emptyOutDir: false`) — я проверил на реальном тесте: `admin/` переживает пересборку без проблем. Обратная сторона — если вы удалите статью или страницу, старый файл сам не удалится из `trustit.by`, это нормально, просто раз в какое-то время можно почистить руками через File Manager.

## 1. Загрузка кода на хостинг

**Папка `trust-site-src` (исходники сайта):**

Вариант А — через **Git Version Control** в cPanel:
1. cPanel → **Git Version Control** → **Create**.
2. Clone URL: `https://github.com/NadyaK86/trustit.git`
3. Repository Path: `/home/ваш_логин/trustit-repo` (временное место — репозиторий содержит и `trust-site/`, и `admin/` вместе)
4. После клонирования — через File Manager скопируйте содержимое `trustit-repo/trust-site` в `trust-site-src`, а содержимое `trustit-repo/admin` — в `trustit.by/admin`.

Вариант Б — проще, если не нужна история изменений: скачайте ZIP репозитория с GitHub, распакуйте, руками разложите папки `trust-site` → `trust-site-src` и `admin` → `trustit.by/admin` через File Manager.

## 2. Настройка Node.js-приложения для админки

cPanel → **Setup Node.js App** → **Create Application**:

| Поле | Значение |
|---|---|
| Node.js version | самая новая доступная (нужна ≥ 20, лучше ≥ 22) |
| Application mode | `Production` |
| Application root | `trustit.by/admin` |
| Application URL | домен `trustit.by`, подпапка `admin` — итоговый адрес `trustit.by/admin` |
| Application startup file | `server.js` |

Жмёте **Create**.

## 3. Переменные окружения

На странице приложения → **Environment variables**:

| Имя | Значение |
|---|---|
| `ADMIN_PASSWORD` | ваш надёжный пароль (минимум 8 символов) |
| `ADMIN_JWT_SECRET` | случайная строка ≥ 24 символов (см. команду ниже) |
| `SITE_PATH` | `/home/ваш_логин/trust-site-src` (**абсолютный** путь — раз исходники теперь не рядом с admin, относительный путь `../trust-site` здесь не подойдёт) |
| `ASTRO_OUT_DIR` | `/home/ваш_логин/trustit.by` (**абсолютный** путь к корню домена — сюда Astro будет писать собранный сайт при нажатии «Собрать сайт») |
| `NODE_ENV` | `production` |
| `SITE_ORIGIN` | `https://trustit.by` |
| `SITE_PREVIEW_URL` | `https://trustit.by` |
| `TELEGRAM_BOT_TOKEN` | токен бота (если уже создали) |
| `TELEGRAM_CHAT_ID` | id чата/канала |

`ADMIN_PORT` / `PORT` не задавайте — cPanel назначает порт сам.

Сгенерировать `ADMIN_JWT_SECRET` на своём Mac:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Замените `/home/ваш_логин/` на реальный путь — точное имя вашей домашней папки на хостинге можно посмотреть в File Manager (обычно видно в адресной строке или в самом верху дерева папок слева).

## 4. Первая сборка сайта

Так как в `trustit.by` пока лежит dist, собранный вручную на Mac, а не через `ASTRO_OUT_DIR` — после того как admin поднимется (шаги 5–6 ниже), просто один раз нажмите «Собрать сайт» в самой админке. Она пересоберёт сайт из `trust-site-src` и запишет результат в `trustit.by`, используя переменную `ASTRO_OUT_DIR` — дальше уже не нужно ничего заливать вручную.

Перед этим не забудьте:
1. В `trust-site-src` создать `.env` (на основе `.env.example`) с:
   ```ini
   PUBLIC_SITE_URL=https://trustit.by
   PUBLIC_LEAD_ENDPOINT=/admin/api/lead
   ```
   (про `/admin/api/lead` вместо `/api/lead` — см. пункт 7 ниже, это важно)

## 5. Установка зависимостей

На странице приложения в cPanel — кнопка **Run NPM Install**. Она установит зависимости `admin/package.json` во внутреннее виртуальное окружение приложения.

Отдельно нужно поставить зависимости и для `trust-site-src` — но у неё нет своего Node.js-приложения в cPanel (это просто исходники, не постоянный процесс). Проще всего сделать это через **Terminal** в cPanel, если он у вас есть в панели (некоторые тарифы hoster.by его дают):
```bash
cd ~/trust-site-src
/opt/cpanel/ea-nodejs22/bin/npm install
```
(точный путь к npm зависит от версии Node, которую cPanel выбрал для вашего домена — если команда не найдётся, гляньте, какая версия Node.js указана на странице вашего Node.js-приложения в cPanel, и подставьте её номер в путь `ea-nodejsXX`)

Если Terminal в панели недоступен — попросите техподдержку hoster.by один раз выполнить `npm install` в этой папке, либо соберите `node_modules` локально на Mac (та же версия Node!) и загрузите архивом через File Manager (менее надёжно из-за разных ОС, но рабочий вариант).

## 6. Запуск

Кнопка **Restart** на странице приложения. Статус должен стать зелёным / "Running".

## 7. Проверка

Откройте `https://trustit.by/admin` — должна загрузиться страница входа. Залогиньтесь.

Если 404/500 — смотрите `stderr.log` в папке `trustit.by/admin/logs` через File Manager.

## 8. Форма заявок на сайте (`/api/lead`)

cPanel проксирует в Node-приложение только то, что попадает под `Application URL` (`trustit.by/admin`). Путь `/api/lead`, которым пользуется форма на **главном** сайте, лежит вне этого префикса — по умолчанию он "провалится" в статику и даст 404.

Решение (уже учтено в шаге 4 выше): в `.env` сайта укажите
```ini
PUBLIC_LEAD_ENDPOINT=/admin/api/lead
```
Тогда форма будет стучаться сразу под `/admin` — попадёт в то же Node-приложение без дополнительных правил в Apache.

## 9. Как публиковать изменения контента дальше

Заходите на `trustit.by/admin`, редактируете, жмёте «Собрать сайт» — сборка запишет результат прямо в `trustit.by`, обновления увидят посетители сразу после завершения сборки.

## Что выбрать: VPS+SSH+PM2 (`DEPLOY.md`) или cPanel (этот файл)?

- **VPS-вариант** — больше контроля, привычная связка nginx+PM2, чуть более гибкая настройка (например, легче добавить редиректы, кэширование, HTTP/2). Требует SSH-доступа и минимальных навыков администрирования Linux.
- **cPanel-вариант** — быстрее стартовать, не нужен SSH и работа с терминалом на сервере, всё через привычный веб-интерфейс. Чуть менее гибкий (например, момент с `/api/lead`, описанный выше).

Раз у вас уже есть SSH-доступ к VPS и оба варианта в целом рабочие — можно ориентироваться на `DEPLOY.md` как на основной путь, а этот файл держать про запас, если вдруг тариф сменится на чисто cPanel-хостинг без root-доступа.
