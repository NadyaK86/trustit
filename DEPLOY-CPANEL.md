# Деплой trustit.by на hoster.by через cPanel (поддомен admin.trustit.by)

Этот способ — для тарифа с cPanel и без root/sudo-доступа (обычный, "ограниченный" Terminal внутри cPanel, если он вообще есть). Используем раздел **«Setup Node.js App»** (он же «Node.js Selector») — cPanel сам поднимает Node-процесс через Phusion Passenger и держит его живым, аналог PM2, но встроенный в панель, без необходимости в root.

## Архитектура

- **`trustit.by`** — статический Astro-сайт. Собирается в свою папку (сейчас там уже лежит `dist`), Apache отдаёт как обычную статику.
- **`admin.trustit.by`** — отдельный **поддомен**, целиком отдан под Node-приложение (админка). Работает независимо от того, куда и как собирается сайт — они физически никак не пересекаются, поэтому никаких специальных мер защиты (типа запрета на очистку папки при сборке) для самой админки не нужно.
- Между ними — **CORS**: форма заявок на `trustit.by` шлёт запрос на `admin.trustit.by/api/lead`, и админ-сервер уже умеет проверять `Origin` и разрешать именно ваш домен (переменная `SITE_ORIGIN`) — это уже реализовано в коде, ничего дополнительно писать не нужно.

```
/home/ваш_логин/
├── trustit.by/              ← корень домена, сюда Astro пишет собранный сайт
│   ├── index.html
│   ├── _astro/
│   └── ...остальные страницы...
│
├── admin.trustit.by/         ← корень Node-приложения (то, что было папкой admin/ в репозитории)
│   ├── server.js
│   ├── package.json
│   └── public/
│
└── trust-site-src/           ← приватная папка с исходниками Astro — НЕ веб-доступна
    ├── src/
    ├── astro.config.mjs
    ├── package.json
    └── public/
```

> Исходники Astro (`src/`, `package.json`, `node_modules`) по-прежнему держим отдельно от публичной папки домена — не потому, что рядом лежит `admin` (её там больше нет), а просто из общей гигиены: посетителям сайта эти файлы не нужны, а держать их в папке, которую видит веб-сервер, — лишний риск.

---

## 1. Создать поддомен

cPanel → **Subdomains** → **Create a New Subdomain**:
- Subdomain: `admin`
- Domain: `trustit.by`
- Document Root: можно оставить предложенный по умолчанию (например `admin.trustit.by`) — именно туда мы положим папку `admin` из репозитория.

## 2. Загрузка кода на хостинг

Вариант А — через **Git Version Control** в cPanel:
1. cPanel → **Git Version Control** → **Create**.
2. Clone URL: `https://github.com/NadyaK86/trustit.git`
3. Repository Path: `/home/ваш_логин/trustit-repo` (временное место, репозиторий содержит и `trust-site/`, и `admin/` вместе)
4. После клонирования через File Manager разложите:
   - содержимое `trustit-repo/admin` → в `admin.trustit.by` (папка, созданная на шаге 1)
   - содержимое `trustit-repo/trust-site` → в новую папку `trust-site-src` (создайте её в File Manager рядом, на уровне домашней папки)

Вариант Б — скачайте ZIP репозитория с GitHub, распакуйте, разложите руками так же, как в варианте А.

## 3. Настройка Node.js-приложения

cPanel → **Setup Node.js App** → **Create Application**:

| Поле | Значение |
|---|---|
| Node.js version | самая новая доступная (нужна ≥ 20, лучше ≥ 22) |
| Application mode | `Production` |
| Application root | `admin.trustit.by` |
| Application URL | поддомен `admin.trustit.by` (без подпапки — приложение занимает весь поддомен) |
| Application startup file | `server.js` |

Жмёте **Create**.

## 4. Переменные окружения

На странице приложения → **Environment variables**:

| Имя | Значение |
|---|---|
| `ADMIN_PASSWORD` | ваш надёжный пароль (минимум 8 символов) |
| `ADMIN_JWT_SECRET` | случайная строка ≥ 24 символов (см. команду ниже) |
| `SITE_PATH` | `/home/ваш_логин/trust-site-src` (абсолютный путь) |
| `ASTRO_OUT_DIR` | `/home/ваш_логин/trustit.by` (абсолютный путь к корню основного домена — сюда будет писаться собранный сайт) |
| `NODE_ENV` | `production` |
| `SITE_ORIGIN` | `https://trustit.by` (именно **основной** домен — это разрешённый источник для CORS на `/api/lead`) |
| `SITE_PREVIEW_URL` | `https://trustit.by` |
| `TELEGRAM_BOT_TOKEN` | токен бота (если уже создали) |
| `TELEGRAM_CHAT_ID` | id чата/канала |

`ADMIN_PORT` / `PORT` не задавайте — cPanel назначает порт сам.

Сгенерировать `ADMIN_JWT_SECRET` на своём Mac:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Замените `/home/ваш_логин/` на реальный путь — посмотрите в File Manager (виден в адресной строке или в дереве папок).

## 5. Настройка сайта перед первой сборкой

В `trust-site-src` создайте `.env` (на основе `.env.example`):
```ini
PUBLIC_SITE_URL=https://trustit.by
PUBLIC_LEAD_ENDPOINT=https://admin.trustit.by/api/lead
```
(теперь это полноценный URL на другой домен — не относительный путь, как было бы при схеме с подпапкой)

## 6. Установка зависимостей

Для `admin.trustit.by` — кнопка **Run NPM Install** на странице Node.js-приложения в cPanel.

Для `trust-site-src` — своего Node.js-приложения в cPanel нет (это просто исходники, не постоянный процесс), поэтому нужен **Terminal** в cPanel (если есть на вашем тарифе):
```bash
cd ~/trust-site-src
/opt/cpanel/ea-nodejs22/bin/npm install
```
(точный путь к `npm` зависит от версии Node — посмотрите, какая указана на странице вашего Node.js-приложения, и подставьте номер в `ea-nodejsXX`)

Если Terminal недоступен — попросите поддержку hoster.by один раз выполнить `npm install` в этой папке, либо соберите `node_modules` локально на Mac (та же версия Node) и загрузите архивом через File Manager.

## 7. Первая сборка

Запустите Node-приложение (кнопка **Restart** на странице приложения в cPanel), откройте `https://admin.trustit.by`, залогиньтесь, нажмите «Собрать сайт». Сборка запишет результат прямо в `trustit.by` — заливать `dist` вручную больше не понадобится.

## 8. Проверка

- `https://admin.trustit.by` — открывается страница логина, вход по паролю работает.
- `https://trustit.by` — сайт открывается, после нажатия «Собрать сайт» видно, что страницы обновляются.
- Отправьте тестовую заявку через форму на сайте — она должна дойти (и в саму админку, и в Telegram, если бот настроен).

Если что-то не так — логи Node-приложения смотрите в File Manager: `admin.trustit.by/logs` (или там, где cPanel указал путь к логам на странице приложения — обычно `stderr.log`).

## 9. Как публиковать изменения контента дальше

Заходите на `https://admin.trustit.by`, редактируете контент, жмёте «Собрать сайт» — обновления сразу видны на `trustit.by`.

---

## Почему поддомен, а не `trustit.by/admin`

Изначально рассматривался вариант с подпапкой (`trustit.by/admin`), но он требует нескольких хрупких компромиссов: обрезки/добавления префикса в путях, запрета Astro на очистку папки при сборке (чтобы не задеть админку, лежащую внутри той же директории), нестандартного адреса для приёма заявок (`/admin/api/lead` вместо `/api/lead`). Поддомен убирает всё это разом — сайт и админка физически никогда не пересекаются, а поддержка CORS для кросс-доменных заявок уже была заложена в код изначально.
